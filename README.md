# tako-core

The terminal engine behind [Tako](https://github.com/alex09x/tako), as a library: a Rust VT core, a Metal terminal view for macOS and iOS, and a session runtime that keeps shells alive when the window goes away.

[![CI](https://github.com/alex09x/tako-core/actions/workflows/ci.yml/badge.svg)](https://github.com/alex09x/tako-core/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

## What is here

| Part | What it is | Where |
| --- | --- | --- |
| **`tako_core`** | The engine, in Rust. It parses what a program writes, keeps the screen and scrollback, and encodes keys and mouse input. It draws nothing and starts no processes. | the root crate, `src/` |
| **`TakoCoreUI`** | Swift views drawn with Metal: `TakoTerminalNSView` (AppKit) and `TakoTerminalView` (UIKit). The engine comes in as a prebuilt `TakoCore.xcframework`. | the root `Package.swift`, `swift/Sources/TakoCoreUI` |
| **`tako-session`** | One small daemon per session owns the PTY and the screen. Clients attach, detach and come back to the same screen, across window closes and app relaunches. | [`tako-session/`](tako-session/README.md) |

The engine supports:

- VT100 and xterm sequences, 256 and 24-bit colour, the alternate screen, scroll regions and left/right margins;
- mouse reporting, bracketed paste, focus events, OSC 8 links, OSC 52 clipboard;
- the Kitty keyboard protocol and Kitty graphics (RGB, RGBA and PNG);
- OSC 7 and OSC 133 shell integration: the working directory, prompts, and each command with its output and exit status;
- scrollback that reflows on resize, and search over it;
- checkpoints: the whole terminal saved and restored byte for byte;
- optional PTY (`features = ["pty"]`) and SSH (`features = ["ssh"]`) back ends;
- a C ABI (`include/prod_vt.h`) and Swift bindings generated by UniFFI.

Details, limits and the versioning rules are in [docs/takocore.md](docs/takocore.md). Which escape sequences are supported and why: [docs/escape-sequence-policy.md](docs/escape-sequence-policy.md).

## Use it

### Swift (macOS 14+, iOS 17+, Apple silicon)

```swift
dependencies: [
    .package(url: "https://github.com/alex09x/tako-core", exact: "0.1.0"),
],
targets: [
    .target(name: "MyApp", dependencies: [
        .product(name: "TakoCoreUI", package: "tako-core"),
    ]),
]
```

SwiftPM downloads `TakoCore.xcframework` from the release and checks it against the checksum in `Package.swift`. The view gets bytes from your program through `feed`, and hands keys, paste and replies back through its delegate. [examples/macos-sample](examples/macos-sample) is a complete window with a login shell in about 200 lines. [examples/ios-sample](examples/ios-sample) is the iOS version.

### Rust

```toml
[dependencies]
tako-core = { git = "https://github.com/alex09x/tako-core", tag = "v0.1.0" }
```

```rust
use tako_core::terminal::Terminal;

let mut term = Terminal::new(80, 24); // columns, rows
term.feed(b"\x1b[1mhello\x1b[0m world\r\n");
println!("{}", term.dump());
```

[examples/headless.rs](examples/headless.rs) runs a real program against the engine with no window.

### C

`include/prod_vt.h` and `include/prod_vt_checkpoint.h` with the static library. [examples/c](examples/c) builds the engine and a small client: `examples/c/build.sh && examples/c/headless`.

### tako-session

Prebuilt binaries for macOS arm64 and Linux x86_64 are on the [`session-v*` releases](https://github.com/alex09x/tako-core/releases), each with a `.sha256` file:

```sh
curl -fLO https://github.com/alex09x/tako-core/releases/download/session-v0.1.0/tako-session-macos-arm64
curl -fLO https://github.com/alex09x/tako-core/releases/download/session-v0.1.0/tako-session-macos-arm64.sha256
shasum -a 256 -c tako-session-macos-arm64.sha256
install -m 755 tako-session-macos-arm64 ~/.local/bin/tako-session

tako-session attach dev      # a shell that survives the terminal; ctrl+\ detaches
tako-session list
```

The commands, environment variables and behaviour are described in [tako-session/README.md](tako-session/README.md). The wire protocol is in [docs/session-protocol.md](docs/session-protocol.md).

## Releases

| Tag | Contains |
| --- | --- |
| `vX.Y.Z` | The Swift package and the Rust crate. `TakoCore.xcframework.zip` holds macOS arm64, iOS and iOS Simulator slices. |
| `session-vX.Y.Z` | The `tako-session` binaries, built by [`release-session.yml`](.github/workflows/release-session.yml) when the tag is pushed. |

To cut an engine release, run `scripts/package-xcframework.sh vX.Y.Z`. It builds the xcframework, regenerates `swift/Sources/TakoCoreUI/Generated/tako_core.swift`, and writes the release URL and checksum into `Package.swift`. Commit those changes, tag the commit, and attach `target/TakoCore.xcframework.zip` to the release. A session release is a `session-vX.Y.Z` tag on a commit whose `tako-session/Cargo.toml` has that version.

## Develop

Builds and tests go through [Mitts](https://mittsbuild.com), not cargo.

| What | Command |
| --- | --- |
| Engine and session tests | `mitts test --workspace --features pty,ssh` |
| Lints | `mitts fmt --all --check`, `mitts clippy --workspace --all-targets --features pty,ssh -- -D warnings` |
| TakoCoreUI tests on macOS | `scripts/swift-test.sh` |
| TakoCoreUI tests on the iOS Simulator | `scripts/test-ios-surface.sh` |
| The xcframework | `scripts/build-xcframework.sh` (`--macos-only` for the host slice) |
| Benchmarks | `mitts bench --bench throughput`, `mitts bench -p tako-session` |

Every pull request runs these on GitHub Actions:
- the lints;
- the engine and session tests on macOS arm64 and Linux x86_64;
- a session benchmark gate on Linux;
- the TakoCoreUI tests on macOS;
- an iOS Simulator build and test run.
